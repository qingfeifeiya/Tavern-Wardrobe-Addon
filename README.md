# 衣柜插件 · Tavern Wardrobe Addon

为 SillyTavern（酒馆）的 USER 和 Char 管理服装参考。在可视化衣柜中导入图片、整理分类与标签、编辑或生成服装描述，再把选中的服装按模板加入后续对话请求。

项目通过**酒馆助手的脚本库**运行，界面、样式与逻辑都在 [`index.js`](index.js) 中，无需安装项目依赖或构建。

## 功能

- **服装管理**：批量导入 PNG、JPEG、WebP 图片，编辑名称、分类、描述和标签，切换网格或列表视图。
- **图片文件存储**：原图通过酒馆接口保存为文件，列表与预览直接加载文件路径；启动时自动迁移旧存档中的内嵌图片。
- **标签与多选**：创建、删除标签，批量归类、导出、删除，以及应用或取消应用到指定角色。
- **穿着归属**：每件服装可分别勾选 USER、Char，只有明确勾选两边才允许共享；未分配的服装不发送。每个角色使用独立的单套、衣柜模板。归属在同一脚本可用的聊天间共用，首页也能设置。
- **AI 描述**：根据图片生成整套服装或指定单品的描述，两类生成提示词可分别修改。
- **发送配置**：支持文字、图片、文字＋图片，以及三种提示词注入位置。
- **图片参考模板**：含图请求附带单套或衣柜图片提示词，默认只参考服饰，忽略图中人物与背景。
- **备份与迁移**：将单件、所选服装或整个衣柜导出为可重新导入的 JSON，包含原图和标签。
- **桌面与手机布局**：桌面使用分类、列表、详情三栏；窄屏可在列表和详情之间切换。

## 安装与打开

### 运行条件

- 已安装并启用酒馆助手的 SillyTavern。
- 酒馆助手提供脚本库、脚本变量、聊天变量、`generateRaw`、`getModelList` 等接口。
- 酒馆使用会触发 `CHAT_COMPLETION_PROMPT_READY` 事件的聊天补全发送流程；本脚本在该事件中注入服装内容。
- 浏览器支持原生 `<dialog>`。使用 AI 看图生成描述或直接发送图片时，相应模型与连接还需支持图片输入。
- 酒馆提供 `/api/images/upload`、`/api/images/delete` 和 `SillyTavern.getRequestHeaders()`，用于保存及删除图片文件。

仓库目前未声明最低 SillyTavern／酒馆助手版本。若提示接口不存在，请先检查酒馆助手是否启用以及接口是否可用。

### 安装步骤

1. 打开仓库中的 [`index.js`](index.js)，点击 **Raw**，复制完整 JavaScript 源码。
2. 在酒馆助手的脚本库中新建脚本，将源码粘贴进脚本编辑器。
3. 保存并启用脚本。可以将脚本命名为“衣柜插件”。
4. 打开酒馆扩展菜单，点击新增的 **衣柜插件** 入口。也可以通过酒馆助手生成的同名脚本按钮打开。

这是酒馆助手脚本，不是通过 SillyTavern 扩展安装器直接安装的扩展包。不要将 GitHub 页面 HTML 粘贴到脚本编辑器，也不要直接用浏览器打开本地 `index.js`。

### 更新

先导出衣柜备份，再用最新的 `index.js` 替换**原脚本**中的源码，保存并重新启用。服装与设置使用该脚本的变量存储；新建另一个脚本不等于更新原脚本，也不会自动继承原脚本的数据。备份文件的具体范围见下文。

## 第一次使用

1. **打开衣柜**：在酒馆扩展菜单打开衣柜面板，无需先进入聊天。
2. **导入图片**：点击“导入服装”；手机端点击底部“导入”。支持一次选择多张图片，默认以文件名作为服装名，分类为“其他”。
3. **填写详情**：选择服装，在“信息”中修改名称和分类，在“描述”中填写款式、颜色、材质等内容。需要 AI 生成时，先配置下文的 API，再选择“服装描述”或“单品描述”，点击“AI 生成描述”。
4. **保存修改**：AI 返回的描述先写入编辑框，点击“保存修改”才会持久保存；勾选穿着归属时也会先保存当前编辑内容。
5. **指定穿着归属**：在详情上方勾选 **USER** 或 **Char**，归属立即保存。只勾 USER 就只给 USER 穿，只勾 Char 就只给 Char 穿；分别勾选两边才允许共享，全部取消则不发送这件服装。卡片底部左侧显示 USER、Char、USER · Char 或“未分配”，右侧标签容器显示已分配标签或“未分组”。
6. **继续聊天**：下一次正常对话生成时，脚本会读取共用的服装选择，并按已保存的发送设置和当前聊天的角色名称注入服装内容。切换聊天后仍沿用这些选择；应用操作本身不会立即请求 AI，也不会新增一条可见的聊天消息。

默认发送方式为**文字描述**，位置为**用户消息末尾**。刚导入的图片没有描述，使用默认方式前需要填写或生成描述；若希望直接发图，可先在“衣柜设置 → 发送内容”中改为“图片”并保存。

### 分类、标签与批量操作

分类包含上装、下装、连衣裙、外套、内衣、袜子、鞋子、配饰、套装和其他。每件服装属于一个分类，并可归入一个自定义标签；未指定标签的服装归入“未分组”。

- 在列表顶部点击 **＋** 创建标签；在详情的“标签”页选择后立即保存归属，可直接切换到该标签筛选。名称、描述等编辑仍需点击“保存修改”。
- 删除标签会把其中服装移回“未分组”，不会删除服装。
- 点击“多选”后勾选服装，出现批量操作栏，可应用／取消应用到 USER 或 Char、移动标签、导出或删除。
- 普通模式下卡片右上角显示爱心 SVG，点击可收藏或取消收藏，状态立即保存；左侧“收藏”显示当前标签下的收藏数量及服装。只有开启“多选”才显示勾选框，此时爱心隐藏。收藏状态随服装 JSON 一起导出和恢复，旧数据默认未收藏。
- 顶部搜索匹配名称、描述、分类和标签，忽略英文大小写与首尾空格，与当前分类、标签共同筛选；清空后恢复当前筛选结果。排序菜单可选择导入顺序、名称升序、名称降序和最近使用，手机端同样可用。
- 左侧“最近使用”显示曾成功应用到 USER 或 Char 的服装，默认按应用时间倒序排列，支持继续搜索和按标签筛选。取消应用保留历史，删除服装时一并移除；记录随服装存档与 JSON 备份保存。旧数据没有使用记录，更新后重新应用即可进入列表。
- “多选”右侧的“一键识图”会统计整个衣柜中有图片且描述为空的记录，确认后使用“服装描述”提示词逐张识别，自动保存名称、描述和标签。已有描述（包括当前编辑框尚未保存的描述）会跳过，纯空白描述视为空。没有待识别图片时直接提示；接口或保存失败会停止，已经保存的结果保留，再次点击可继续识别剩余图片。切换详情服装、关闭衣柜或卸载脚本会取消剩余识图。
- “全选”只选择当前分类、标签和搜索条件下**可见的服装**；切换筛选会清除勾选。退出多选不会取消角色已经应用的服装。
- 批量操作使用已保存的数据；编辑详情后应先保存，再进行批量操作。

USER／Char 指你手动指定的穿着归属，不代表男装／女装，也不会根据人物性别自动分配或共享。批量“应用到”会给指定角色增加归属，保留另一边已有的归属；批量“取消应用”只移除指定角色。已有的角色清单会直接显示为相应勾选状态。

## 衣柜设置

点击面板右上角齿轮打开设置。各设置页修改后均需点击该页的“保存”。

### 导入／导出数据

设置侧栏的“导入／导出数据”用于迁移五类设置：发送内容、USER 模板、Char 模板、图片模板、描述生成提示词。

- **导出数据**：下载 `衣柜设置.json`，只包含已经保存的上述设置。未保存的表单修改不导出，空衣柜也可导出。
- **导入数据**：选择该文件，全部校验通过后一次替换这五类设置，并立即刷新相应表单。文件错误或保存失败时保留原设置。
- **API 信息始终排除**：不导出连接方式、地址、模型、密钥、温度、Token 参数或其他 API 配置；导入文件夹带的 API 字段也不会写入或覆盖当前连接。
- **服装与原图单独备份**：此文件不含服装、图片、标签或 USER／Char 应用选择；这些数据继续使用衣柜中的“导入服装”和“导出服装”。

文件格式为 `format: "tw-wardrobe-settings"`、`version: 1`，与服装 JSON 分开。导入发送类型时仍检查已应用服装是否具备所需的描述或图片，避免导入后无法发送。

### API 连接

此处的连接用于**生成服装描述和测试连接**。正常聊天仍使用 SillyTavern 当前的聊天连接；选择自定义 API 不会替换酒馆的聊天接口。

| 连接方式 | 配置方式 |
| --- | --- |
| 使用酒馆连接 | 默认选项，沿用酒馆当前连接，无需另外填写接口和密钥。 |
| 自定义（OpenAI 兼容） | 填写服务商提供的接口地址、API Key、模型、温度及最大回复 Token。地址必须使用 HTTP 或 HTTPS。 |

自定义连接可点击“获取模型”再从列表选择，也可手动输入模型名。接口没有返回模型列表时，仍可手动填写模型并测试连接。

“测试连接”使用表单当前值发送一条要求回复 `OK` 的短请求，收到非空文本即视为连接成功；它不验证模型是否支持看图，也不代表配置已保存。测试后点击“保存”，服装描述生成才会使用这份配置。连接测试与描述生成均不携带聊天历史，不写入聊天记录。

API Key 保存在酒馆助手的脚本变量中，密码输入框只负责遮挡显示，不代表加密存储。分享脚本变量或酒馆数据备份前，请检查是否包含密钥。

### 发送内容与位置

| 内容类型 | 实际发送内容 | 应用前要求 |
| --- | --- | --- |
| 文字描述 | USER／Char 对应的文字模板 | 每件服装有非空描述 |
| 图片 | 图片提示词＋原图；默认不附加已保存的服装描述 | 每件服装有图片，聊天模型与连接支持图片输入 |
| 文字＋图片 | 角色文字模板＋图片提示词＋原图 | 每件服装同时有描述和图片，聊天模型与连接支持图片输入 |

图片以真实的 `image_url` 内容块发送，不是把图片地址作为文字发送。“图片”模式仍附带图片模板中的文字，以说明服饰参考范围；自定义图片模板也可以主动引用描述变量。

| 注入位置 | 行为 |
| --- | --- |
| 系统提示末尾 | 追加到请求开头连续系统消息中的最后一条；没有系统前缀时，在开头新增系统消息。 |
| 上下文末尾 | 在整个请求消息数组最后新增一条系统消息。 |
| 用户消息末尾 | 追加到最后一条用户消息；没有用户消息时，在末尾新增用户消息。 |

注入修改的是本次请求载荷，保留原消息已有的文本、图片及其他字段。切换发送类型时，脚本会检查共用选择中已应用的服装是否满足新类型要求；缺少描述或图片时会提示保存失败。

### USER、Char 与图片模板

USER 和 Char 分别有“单套模板”和“衣柜模式”模板：该角色选择 **1 套**时使用单套模板，选择**多套**时使用衣柜模板。两者独立计算，例如 USER 选一套、Char 选三套时，会分别使用 USER 单套模板与 Char 衣柜模板。

每组发送内容都会先标明 USER／Char 及其当前名称，并说明文字和紧随其后的图片只对应该角色，另一角色只能使用自己清单中列出的服装。这份归属说明在自定义模板下也会保留；同件服装只有明确分配给两边时，才会出现在两份清单中。

图片模板也分为单套与衣柜两种，仅在含图发送方式下附加。默认衣柜模板提示 AI 根据剧情选择一套，而不是同时穿上全部服装；这属于提示词约束，不会自动替用户改变应用选择。

默认文字及图片模板要求禁止编造服装，并将细节分散融入动作、触感和环境互动，每次只带出一两个细节。衣柜模式还要求按场景标签匹配穿搭，在场景转换时切换。发送内容会附带该角色服装的名称、编号与实际标签对应关系，图片模式也会携带；未分组的服装不补造场景标签。

更新脚本时，仍与上一版原始默认值完全相同的模板会自动使用新版内容；已经编辑过的自定义模板保留。Char 模板使用小写变量 `{{char}}`。

| 变量 | 含义 |
| --- | --- |
| `{{user}}` | 当前聊天的用户名 |
| `{{char}}` | 当前聊天的角色名 |
| `{{wearer}}` | 这组服装所属的 USER 或 Char 的实际名称 |
| `{{name}}` | 服装名称；多套时以顿号连接 |
| `{{description}}` | 服装描述；多套时以换行连接 |
| `{{outfits}}` | 带编号的服装名称与描述列表 |
| `{{count}}` | 当前角色所选服装的数量 |

例如，单套文字模板可以写为：

```text
{{wearer}} 当前穿着「{{name}}」：
{{description}}
请在后续描写中保持服装细节一致。
```

模板只替换表中变量，不执行代码，也不会再次解释服装名称或描述中原有的模板标记。

### 描述生成提示词

“描述生成”页可分别编辑：

- **服装描述**：描述图片中可见的整套服饰与配饰。
- **单品描述**：围绕当前服装名称和分类描述目标单品，忽略其他服饰。

这两类提示词支持 `{{name}}`（当前已保存的服装名称）与 `{{category}}`（中文分类名称）。先保存名称、分类及提示词，再到详情“描述”页选择类型并生成。

如果希望 AI 同时命名服装，可在任一种提示词中要求仅返回 JSON，例如：

```json
{"name":"黑金长外套","description":"黑色长款外套，搭配金色滚边与腰带。","category":"日常"}
```

脚本会分别将 `name` 和 `description` 填入名称与描述编辑框，也兼容完整的 JSON 代码块。两个字段必须为非空字符串；JSON 格式或字段错误时会显示提示并保留原内容。点击“保存修改”或勾选穿着归属后，USER／Char 的单套、衣柜模板即可使用更新后的 `{{name}}`、`{{description}}` 和 `{{outfits}}`。

生成请求会附带现有标签，要求 AI 根据图片判断 `category`。这里的输出字段 `category` 表示**自定义标签名称**：同名标签复用，没有则创建，并立即保存服装的标签归属，不改变上装、外套等内置分类。旧 JSON 只有 `name`、`description` 时保留原标签；原有纯文本回复仍只更新描述，保留名称与标签。

默认提示词要求忽略人物身份、面容、发型、姿势、身体特征和背景，不猜测不可见细节。模型生成的内容仍可在编辑框中修改，然后保存或应用。

## 数据保存、备份与恢复

| 数据 | 保存范围 |
| --- | --- |
| 服装信息、图片路径、标签 | 当前脚本的变量，在同一脚本可用的聊天间共享 |
| 原图文件 | 酒馆当前用户的数据目录下 `user/images/tavern_wardrobe/` |
| API 配置、发送设置、角色／图片模板、描述生成提示词 | 当前脚本的变量 |
| USER／Char 已应用的服装 ID | 当前脚本的变量，首页可设置，切换聊天后沿用共用选择 |

### 图片保存与旧数据迁移

导入图片和恢复 JSON 时，通过酒馆原生 `/api/images/upload` 接口将 Base64 解码成 PNG、JPG 或 WebP 文件，保留原图字节，不重新压缩或裁剪。通常位于 `SillyTavern/data/<用户>/user/images/tavern_wardrobe/`；以实际配置的数据目录为准。脚本存档只记录 `user/images/tavern_wardrobe/文件名.png` 这样的相对路径。

列表和预览直接加载图片路径，由浏览器处理缓存，列表使用懒加载。向 AI 发送图片、生成描述或导出备份时，才读取文件并恢复为图片数据地址；同一图片在脚本本次运行期间共用读取缓存，卸载时释放。

更新原脚本后，启动会逐张迁移存档中已有的 `data:image`。每张图片上传并成功保存路径后，才替换对应的内嵌数据；失败时保留尚未迁移的原图，下次启动继续，不需要手动重新导入。迁移保留服装信息、标签和 USER／Char 应用状态，也不会重填正在编辑的详情表单。

删除服装或“删除图片”时，先保存存档，再调用 `/api/images/delete` 清理不再被服装引用的文件。保存失败不会删除原图；文件删除失败会记入浏览器控制台，不撤销已保存的删除操作。导入中途失败或存档保存失败时，会尝试清理本批新上传的文件。

### 导出

- 左侧“导出服装”或手机底部“导出”：导出整个衣柜，保留空标签。
- 详情“导出”：先保存当前编辑，再导出这一件服装及其关联标签。
- 多选后的“导出”：导出所选服装及其关联标签。

JSON 文件标记为 `format: "tw-wardrobe"`、`version: 1`，包含 `groups` 和 `items` 数组。导出时会读取原图，以 Base64 数据地址嵌入，备份可跨设备恢复，也兼容旧版衣柜。较大的原图仍会增加备份文件和含图请求的体积，但不会作为 Base64 反复写入日常存档。图片读取失败时会提示错误，不生成缺失原图的备份。

**服装 JSON 不包含 API 配置、密钥、发送设置、模板、描述生成提示词或角色应用状态。** 发送设置、模板和描述生成提示词可通过“衣柜设置 → 导入／导出数据”单独迁移；API 连接需要在目标酒馆自行配置。

### 恢复与合并

通过“导入服装”选择本插件导出的 JSON，也可以同时选择多份 JSON 或图片。

同时兼容 [Outfit Manager](https://github.com/wenshui012/Outfit-Manager) 导出的 User、单角色、全部角色和完整备份 JSON，仍使用“导入服装”入口，无需转换文件：

- 保留服装和单品的名称、描述、原图、收藏，纯文字记录也可导入。整套穿搭归入“套装”，单品优先匹配现有分类，其余归入“配饰”。
- 场景 `sceneTag` 转为本衣柜标签；没有场景时，使用原分类和子分类作为标签，同名标签复用。
- 完整备份合并 User、角色及通用衣柜，全部角色备份合并其中所有角色；不额外导入预设中的服装副本。
- 支持内嵌 `imageData` 和通过 `_assets` 打包的服务端原图；备份只有图片路径却缺少原图时，整批导入失败并提示重新导出。
- 对方的套装搭配关系不迁移，关联单品作为独立服装导入；不迁移对方的应用选择、API、模板或其他设置，导入后按本衣柜方式重新选择 USER／Char。

- 导入采用**新增合并**，不会覆盖同名服装；重复导入同一备份会增加副本。
- 服装会生成新 ID，同名标签会复用；导入后需重新应用到 USER／Char。
- 同一批文件全部读取与校验成功后才保存；有文件失败时不提交该批新增数据。
- 兼容旧版内嵌图片的 JSON，恢复时重新上传为图片文件。只有本机图片路径的 JSON 会明确报错；请在原酒馆中重新导出包含原图的备份。
- 删除服装会同时移除图片，并清理共用的应用选择。删除前可先导出。

旧版没有标签字段的服装可继续读取，缺少图片模板的设置会补入默认值。尚未保存共用选择时，首次读取到当前聊天的旧应用状态会将其迁移到脚本变量；旧版 `wardrobe_active_id` 单套选择兼容为 Char 的选择。此后其他聊天的旧状态不会覆盖共用选择，取消全部应用也不会恢复旧选择。

## 当前限制与常见问题

| 情况 | 说明或处理方式 |
| --- | --- |
| 搜索后找不到服装 | 搜索与当前分类、标签共同筛选，支持名称、描述、分类和标签。清空搜索、切回“全部”和所有标签后再检查；排序菜单可选择导入顺序、名称升序、名称降序或最近使用。 |
| “收藏”“最近使用”没有内容 | 点击卡片右上角爱心可加入收藏；成功应用到 USER 或 Char 后才会留下最近使用记录，旧数据需重新应用一次。两类列表均遵循当前标签和搜索条件。 |
| 想直接新建纯文字服装 | 当前没有独立的新建纯文字入口。可以导入图片、填写描述后，在“信息”页删除图片，保留文字记录；若正在以含图方式应用，需先取消应用或改为文字方式。 |
| 找不到衣柜入口 | 确认源码完整、脚本已启用，并运行在酒馆助手脚本库中；启动时需要酒馆扩展菜单。失败信息会显示为“衣柜插件启动失败”。 |
| 提示需要打开聊天 | 旧版将应用选择保存在聊天变量中。将最新源码更新到原脚本后，首页即可应用服装，切换聊天沿用共用选择。 |
| 提示需要文字描述／图片 | 补充对应数据，或在“发送内容”中选择符合现有数据的类型并保存。 |
| 模型列表为空 | 检查地址、密钥及列表权限，也可手动输入模型名再测试；空列表本身不能证明密钥无效。 |
| 测试连接成功，但无法看图 | 测试只验证文本响应。请确认用于描述生成或正常聊天的相应模型与连接支持图片输入。 |
| 应用了服装，但聊天界面没有新消息 | 应用只影响后续生成请求，属于正常行为。若模型回复没有体现服装，请检查当前聊天选择、已保存模板及聊天补全发送流程。 |

当前测试使用模拟宿主验证逻辑，不代表所有酒馆版本、浏览器、模型或接口均已完成实际联调。
