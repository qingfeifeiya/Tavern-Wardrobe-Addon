# 衣柜插件 · Tavern Wardrobe Addon

为 SillyTavern（酒馆）的 USER 和 Char 管理服装参考。在可视化衣柜中导入图片、整理分类与标签、编辑或生成服装描述，再把选中的服装按模板加入后续对话请求。

项目通过**酒馆助手的脚本库**运行，界面、样式与逻辑都在 [`index.js`](index.js) 中，无需安装项目依赖或构建。

## 功能

- **独立大分类**：顶部提供“SFW”“NSFW”和“新增空衣柜”，像切换桌面一样切换整套衣柜。服装、标签、搭配、收藏和各穿搭范围的角色归属互相独立；导入及聊天发送使用当前大分类，导出弹窗可选择一个独立衣柜，API、提示词和发送设置共用。现有数据保留在 SFW 分区，并记住上次打开的大分类。
- **服装管理**：从图片文件夹显示缩略图，直接点击勾选，无需 Ctrl／Shift；也可分次添加文件、批量拖放或粘贴 PNG、JPEG、WebP 图片。重复项按名称与原图哈希选择跳过、覆盖或保留两份；支持编辑名称、分类、描述和标签，切换网格或列表视图。
- **图片文件存储**：原图通过酒馆接口保存为文件，列表与预览直接加载文件路径；支持替换或补上传图片，聊天可发送压缩参考图或原图，启动时自动迁移旧存档中的内嵌图片。
- **标签与多选**：创建、重命名、排序和删除标签，批量修改分类、添加／移除标签、收藏／取消收藏、导出、删除，以及应用或取消应用到指定角色。
- **快捷筛选**：按已分配 USER、已分配 Char、未分配、缺描述、无图片筛选；缺描述列表可配合一键识图补全。
- **穿着归属**：每件服装可分别勾选 USER、Char，只有明确勾选两边才允许共享；未分配的服装不作为独立候选发送。每个角色使用独立的单条、衣柜模板。穿搭范围可选全局、按角色卡或按聊天，全局范围在首页也能设置。
- **AI 描述**：根据图片生成整套服装或指定单品的描述，两类生成提示词可分别修改。
- **自由搭配与剧情选装**：AI 可从上装、下装、鞋等单品组成一身，也可选择套装或保存的搭配并补充衣物；首次按剧情选装，后续只在合理换装机会调整，完整记住整身穿着。
- **发送配置**：支持文字、图片、文字＋图片，以及三种提示词注入位置。
- **图片参考模板**：含图请求附带单条或衣柜图片提示词，默认只参考服饰，忽略图中人物与背景。
- **备份与迁移**：将单件、所选服装或整个衣柜导出为可重新导入的 JSON，包含原图和标签。
- **桌面与手机布局**：桌面使用分类、列表、详情三栏；窄屏可在列表和详情之间切换。
- **排错日志**：搜索框右侧的“日志”打开独立弹窗，支持 Error、Warn、Debug、Info、API 请求筛选、关键词搜索、展开详情、复制全部、导出 JSON 和清空。

## 安装与打开

### 运行条件

- 已安装并启用酒馆助手的 SillyTavern。
- 酒馆助手提供脚本库、脚本变量、聊天变量、`getScriptId`、`deleteVariable`、`generateRaw`、`getModelList` 等接口；浏览器允许当前酒馆站点使用 `localStorage`。
- 酒馆使用会触发 `CHAT_COMPLETION_PROMPT_READY` 事件的聊天补全发送流程；本脚本在该事件中注入服装内容。
- 浏览器支持原生 `<dialog>`。使用 AI 看图生成描述或直接发送图片时，相应模型与连接还需支持图片输入。
- 酒馆提供 `/api/images/upload`、`/api/images/delete` 和 `SillyTavern.getRequestHeaders()`，用于保存及删除图片文件。

仓库目前未声明最低 SillyTavern／酒馆助手版本。若提示接口不存在，请先检查酒馆助手是否启用以及接口是否可用。

### 安装步骤

1. 打开仓库中的 [`index.js`](index.js)，点击 **Raw**，复制完整 JavaScript 源码。
2. 在酒馆助手的脚本库中新建脚本，将源码粘贴进脚本编辑器。
3. 保存并启用脚本。可以将脚本命名为“衣柜插件”。
4. 打开酒馆扩展菜单，点击新增的 **衣柜插件** 入口。也可以通过酒馆助手生成的同名脚本按钮打开。

这是酒馆助手脚本，不是通过 SillyTavern 扩展安装器直接安装的扩展包。不要将 GitHub 页面 HTML 粘贴到脚本编辑器，也不要直接用浏览器打开本地 `index.js`。

### 更新

先导出衣柜备份，再用最新的 `index.js` 替换**原脚本**中的源码，保存并重新启用。服装与设置使用该脚本的变量存储；新建另一个脚本不等于更新原脚本，也不会自动继承原脚本的数据。备份文件的具体范围见下文。

## 第一次使用

1. **打开衣柜**：在酒馆扩展菜单打开衣柜面板，无需先进入聊天。
2. **导入图片**：点击“导入服装”；手机端点击底部“导入”。在导入面板点击“选择图片文件夹”，选定文件夹后，在插件内直接点击缩略图勾选，最后点击“导入所选”；文件夹图片默认不勾选，可用“全选／全不选”批量调整。“添加图片/文件”支持分次选择并累积图片或备份 JSON，取消系统文件窗口不会清空之前的选择。系统文件窗口本身仍遵循 Windows 的 Ctrl／Shift 多选规则；无需修饰键的勾选发生在插件的缩略图面板中。默认以文件名作为服装名，分类为“其他”。
3. **填写详情**：选择服装，在“信息”中修改名称、分类和 SFW／NSFW 分级，在“描述”中填写款式、颜色、材质等内容。需要 AI 生成时，先配置下文的 API，再选择“整套描述”或“单品描述”，按需开启或关闭“AI 分类”“AI 标签”，点击“AI 生成描述”。这些选项与服装分类、分级均显示下拉箭头。
4. **保存修改**：AI 返回的描述先写入编辑框，点击“保存修改”才会持久保存；也可直接在描述框粘贴包含 `name`、`description` 及可选 `category`、`tags` 的 JSON（支持完整 JSON 代码块），保存时拆分名称、分类和标签，描述框与存档描述只保留 `description` 正文。勾选穿着归属时也会先保存当前编辑内容。
5. **指定穿着归属**：在服装详情的 **信息 → 专属角色** 输入一个剧情角色名，按回车生成标签。可继续添加名字，点击标签上的 **×** 可移除，最后点击 **保存修改**。普通归属可勾选 **USER** 或 **Char**，勾选即时保存，两边都勾选时才共享。卡片底部会显示已保存的归属。
6. **继续聊天**：下一次正常对话生成时，脚本会读取当前穿搭范围的服装选择，并按已保存的发送设置和当前聊天的角色名称注入服装内容。应用操作本身不会立即请求 AI，也不会新增一条可见的聊天消息。

默认发送方式为**文字描述**，位置为**用户消息末尾**。刚导入的图片没有描述，使用默认方式前需要填写或生成描述；若希望直接发图，可先在“衣柜设置 → 发送内容”中改为“图片”并保存。

导入他人的数据前，先选择用于存放该数据的衣柜，或点击顶部“新增空衣柜”输入名称，再添加图片/文件。每个衣柜都有独立的服装分类和标签面板，切换不会合并数据；切回“SFW”即可继续使用原有衣柜。切换后会清空搜索和多选，详情中尚未点击“保存修改”的内容遵循现有切换服装的行为，不自动保存。衣柜备份一次包含一个衣柜，可在导出弹窗选择要备份的分区，无需先切换当前衣柜。

选中自建衣柜后，点击顶部垃圾桶并确认，即可删除该衣柜及其中的服装、标签和穿搭设置。删除后自动切回 SFW。SFW 和 NSFW 是固定分区。

导入面板在确认前只显示待选文件，不下载链接、上传图片或修改存档；文件夹入口仅列出 PNG、JPEG、WebP 图片，包含其子文件夹。失败时保留勾选供重试，取消面板会清空待选列表。也可把图片或备份 JSON 拖入衣柜，或在衣柜非输入区域粘贴剪贴板图片：导入面板打开时累积到待选列表，其他时候直接沿用原有导入流程；输入框保留原生文字粘贴。

### 分类、标签与批量操作

分类包含上装、下装、连衣裙、外套、内衣、袜子、鞋子、配饰、套装和其他。每件服装属于一个分类，并可同时拥有多个自定义标签，例如“居家”“夏季”“正式”；没有任何标签的服装归入“未分组”。

详情“信息 → 分级”可选 **未标注、SFW（日常／非色情）、NSFW（色情／成人）**，点击“保存修改”生效。新导入图片和旧数据默认未标注，不自动判断分级；分级随服装 JSON 备份保存。三种发送模式都会在固定候选清单和当前穿着中附上分级，不依赖自定义模板是否引用描述。搭配包含 NSFW 成员时，发送时整套按 NSFW 标示，同时保留成员各自分级，即使整套手动标为 SFW 或覆盖了合并描述也不会隐藏成员标记。此标记用于帮助模型判断服装性质和场景适用性，不会自动开启色情剧情，也不能保证模型一定按预期处理。

“衣柜设置 → 发送内容 → 服装分级”提供 **发送 SFW / NSFW 分级** 开关，默认开启，修改后需点击该页“保存”。关闭时不向模型发送候选、搭配成员、当前穿着的分级和分级说明，服装上已保存的标记仍保留，重新开启即可恢复；开关随设置备份保存。开启时分级也只说明服装性质，不直接禁止 NSFW 服装外穿，具体穿搭由角色设定、世界观和剧情场景决定。

- 列表顶部的分组栏只显示当前分类或快捷筛选的相关标签，超出宽度时显示横向滚动条。左侧依次固定放置 **新增标签** 和 **管理标签**，右侧标签独立横向滚动；其下方的独立操作栏放置 **多选、合并搭配、一键识图**。切换筛选分别记住上次选择的标签；“全部”汇总整个衣柜的标签，同名只显示一个。
- 点击 **新增标签** 为当前筛选创建标签，空标签也会保存；其他筛选创建同名标签时合并名称并分别保留筛选归属。旧存档的标签按对应服装出现在相关筛选中，原有空标签保留在“全部”。在详情的“标签”页打开多选下拉框，输入关键词搜索后勾选或取消标签，每次操作立即保存；选中项显示紫底白勾并整行高亮；收起时显示已选数量和标签名称，过长省略且悬停可查看完整名称，下拉选项在固定高度内滚动，支持数百个标签。按 Escape 或点击框外可收起；取消全部勾选即为“未分组”。服装会出现在每个已勾选标签的筛选结果中，卡片最多显示前两个标签，超出显示 `+N`；标签保持单行，过长省略，鼠标悬停标签区域可查看全部名称。名称、描述等编辑仍需点击“保存修改”。
- 点击“新增标签”右侧的铅笔图标打开“管理标签”，只列出当前筛选的分组。可以直接修改名称，拖动 ⠿ 或使用 ↑／↓ 调整顺序，点击“保存”一次生效；取消或按 Escape 会放弃名称和顺序草稿。名称不能为空，重名自动合并并保留服装关联。分类或快捷筛选中重命名、删除只调整该筛选及其中的服装，其他筛选保存的空标签与范围外服装保留；“全部”中操作作用于整个衣柜。筛选归属、空标签及顺序随存档和整库备份保留。
- 详情标签下拉框的搜索框右侧也有 **新增标签**：搜索内容会预填为标签名，确认后立即创建并勾选到当前服装，同名标签直接复用。下拉框保持展开，名称和描述草稿保留；取消或保存失败不会新增标签或改变归属。
- 在“管理标签”勾选单个标签或全选，点击 **删除所选** 并确认即可立即批量删除。其余标签的名称与顺序草稿仍通过“保存”提交。删除标签保留服装及其他标签；没有剩余标签时才归入“未分组”。
- 点击“多选”立即显示下方批量操作栏，未勾选时显示“已选 0 件”且批量操作禁用；勾选服装后，可应用／取消应用到 USER 或 Char、移动到其他衣柜、添加／移除标签或清空标签、修改分类、收藏／取消收藏、导出或删除。修改分类、收藏或移动立即保存；保存失败保留原状态。
- 跨衣柜整理：例如在 NSFW 衣柜勾选衣服，点击“移动到 → SFW”。服装会从原衣柜移出，保留图片、描述、分类、内容分级、收藏、最近使用和标签；目标衣柜的同名标签自动复用，同名服装保留为独立记录。原衣柜中各范围的角色应用及当前穿着一并清理，目标衣柜需重新应用 USER／Char。移动搭配会连同成员一起移动；成员仍被原衣柜其他搭配引用时，请一起勾选相关搭配，或先编辑搭配移除成员。
- 普通模式下卡片右上角显示爱心 SVG，点击可收藏或取消收藏，状态立即保存；左侧“收藏”显示当前标签下的收藏数量及服装。只有开启“多选”才显示勾选框，此时爱心隐藏。收藏状态随服装 JSON 一起导出和恢复，旧数据默认未收藏。
- 顶部搜索匹配名称、描述、分类、标签和服装 ID，忽略英文大小写与首尾空格，与当前分类、标签共同筛选；清空后恢复当前筛选结果。排序菜单可选择导入顺序、名称升序、名称降序和最近使用，手机端同样可用。
- 左侧“最近使用”显示曾成功应用到 USER 或 Char 的服装，默认按应用时间倒序排列，支持继续搜索和按标签筛选。取消应用保留历史，删除服装时一并移除；记录随服装存档与 JSON 备份保存。旧数据没有使用记录，更新后重新应用即可进入列表。
- 左侧新增“已分配 USER”“已分配 Char”“未分配”“缺描述”“无图片”。归属按当前穿搭范围统计，共享服装同时出现在 USER 和 Char 中；这些筛选与标签、搜索共同生效，手机分类菜单也包含相同选项。“未分配”只显示描述完整且未分配给 USER 或 Char 的服装；“缺描述”包含纯空白描述，搭配按成员描述或手动覆盖的整套正文判断；“无图片”表示记录没有关联图片。
- “多选”右侧的“一键识图”会统计整个衣柜中有图片且描述为空的记录；在“缺描述”筛选下，只识别当前标签和搜索条件中可见且有图片的记录。确认后使用“整套描述”提示词识别，最多同时处理 **2 张**，任一张识别并保存后立即接下一张，不必等待另一张。逐张自动保存名称、描述，以及已开启的 AI 分类和标签分组，整批沿用开始时的选项；新标签确认与保存依次处理。已有描述（包括当前编辑框尚未保存的描述）会跳过，纯空白描述视为空。没有待识别图片时直接提示；接口或保存失败会停止全部进行中的识图，已经保存的结果保留，再次点击可继续识别剩余图片。切换详情服装、关闭衣柜或卸载脚本会取消全部进行中及排队的识图。
- “全选”只选择当前分类、标签和搜索条件下**可见的服装**；切换筛选会清除勾选。退出多选不会取消角色已经应用的服装。
- 批量操作使用已保存的数据；编辑详情后应先保存，再进行批量操作。

详情顶部先显示“可穿者”，其下并排展示正面、背面图片，左正面、右背面；缺图时保留对应占位。点击图片可放大对应原图，搭配可分别点击各成员图片；支持键盘 Enter／空格打开，点击关闭按钮或按 Escape 返回，无图位置不打开弹窗。

图片下方依次提供“替换正面图片”“替换背面图片”和“删除图片”。两个替换入口也可为缺图的一面补上传，各自只修改对应图片；“删除图片”会清空正面和背面。旧记录的原图继续作为正面，不自动生成背面。替换保留服装 ID、名称、描述、分类、标签、收藏和 USER／Char 归属，也保留详情中的未保存草稿；上传或存档失败时保留旧图，成功保存后回收不再被引用的旧文件。正背面均随 JSON 备份保存，识图与含图聊天会使用已有的两面，只有一张时仍可正常使用。

USER／Char 指你手动指定的穿着归属，不代表男装／女装，也不会根据人物性别自动分配或共享。批量“应用到”会给指定角色增加归属，保留另一边已有的归属；批量“取消应用”只移除指定角色。已有的角色清单会直接显示为相应勾选状态。

### 合并搭配

「套装」是服装分类，「单品描述」是识图模式。AI 可以直接从独立单品自由搭配；需要固定多件服装的组合关系时，使用「搭配」保存。

1. 直接点击「多选」右侧的 **＋合并搭配** 打开弹窗，无需先开启多选或勾选服装；若已有勾选，会自动带入弹窗作为预选。
2. 填写搭配名称，在弹窗中增减成员。拖动 ⠿ 或使用 ↑／↓ 调整顺序，再点击 **保存搭配**。弹窗列出所有分类的普通服装。重新编辑时，已选成员按保存顺序排列。
3. 在左侧 **搭配**（手机端分类菜单）中选择保存的搭配，勾选 **USER／Char**。保存的搭配作为一条候选提供，AI 选用时保留全部成员，可补充另外分配的独立单品。

组合不限品类或同类数量，可保存“上装＋下装＋鞋”“套装＋配饰”“套装＋上衣”“套装＋袜子＋鞋”，也可加入多件配饰或叠穿衣物。普通「套装」记录可以作为成员；选中已有搭配再次合成时会展开、合并其成员，避免嵌套搭配。

详情“描述”页上方的独立容器中提供 **编辑搭配**，用于调整成员，预览显示各成员图片与名称；下方唯一描述编辑框直接填入合并后的完整描述，可直接修改并保存。未编辑正文时继续自动引用成员，修改单品后搭配同步更新；手动修改并保存后，以编辑后的整套正文显示和发送，不再追加成员描述，也不改动原单品。创建搭配不会自动改变原有 USER／Char 选择。成员仅通过搭配间接分配时不能拆出来独立选用；如果另外明确勾选该成员的角色归属，则仍作为独立候选。同一单品可用于多套搭配，也可明确分配给另一角色。

文字模式使用自动合并描述时要求每个成员有描述，手动编辑整套正文后则要求该正文非空；图片模式要求每个成员有图片，图文模式要求文字和图片都完整。发送时明确列出每条候选的类型、分类、ID、搭配成员和参考图对应关系；同一角色的共享成员图片只发一次，各候选引用同一个图号。一套保存的搭配计一条候选；切换由 AI 根据提示词和剧情完成，插件不会自动改动分配勾选状态。

导出搭配会一并打包成员及其原图、标签，共享单品只导出一次；重新导入会恢复成员关联，支持跳过、覆盖和保留两份。删除仍被搭配引用的单品前，需在“编辑搭配”中移除它，或把关联搭配一并删除；删除搭配本身会保留单品。

### 当前穿着与剧情换装

给角色分配的记录是**可选衣柜**，其中多条记录可以共同组成一身。比如分配 10 件上装、10 件下装、10 双鞋后，AI 可以选“上装 A＋下装 B＋鞋 C”，也可以选“连衣裙＋鞋”或“保存的搭配＋外套”。默认不会把全部候选同时穿上；衣物不足时不编造衣柜外的服装。

首次根据剧情、已有标签和服装资料选装。之后保持完整当前穿着，仅在明确换衣、回家准备、时间跳转等合理机会调整。从客厅到阳台这类普通转场保持原穿搭。

详情中的 **USER／Char** 仅用于分配可选服装；实际穿着由剧情换装记录自动跟踪，列表会显示“当前”或“随搭配穿着”状态。

在 **衣柜设置 → 发送内容 → 换装记录** 选择 **独立 API 选装** 并保存。每次发送时，插件先用 API 页已保存的连接，根据候选衣柜、本次用户输入及设定数量的前文判断穿搭。历史楼层数默认 **2**，可修改为任意非负整数。填 **0** 时只读取本次用户输入，历史不足时发送现有可见楼层。主请求随后发送，候选清单只供选装接口使用。主请求的系统提示只附实际穿搭，含图模式额外附实际穿着的独立参考图消息，用户消息原文保留。

选装通过酒馆后端单独发送，仅在原生聊天发送时运行，避免其他插件收到第二次生成事件。选装结果保存在本次用户楼层的变量中。酒馆内置生图和通过酒馆助手 `generateRaw` 编写生图提示词的插件，会在聊天补全请求中复用已保存的实际穿搭。辅助生成只读当前穿着，无需再次选装。

独立选装还会在新 AI 回复末尾写入隐藏注释，方便直接读取楼层原文的第三方插件按 ID 获取穿搭。格式为 `<!-- outfit:char={"ids":["id"],"items":{"id":{"name":"服装名","description":"衣柜原文"}}} -->`，USER 使用 `outfit:user`。纯图片发送模式在注释里保留名称，描述为空。后续聊天请求会剥离这些注释。

选装失败时主请求继续使用已有穿搭，诊断详情见衣柜日志。启用后每次新输入多一次请求，主回复会等待选装完成。使用自定义 API 时，设置数量的聊天内容会发送给该连接。

原有模式继续兼容。默认的“只存不发”读取 AI 隐藏记录，并在发送前从历史副本中剥离。“保留历史”会继续发送记录。“关闭”保留旧存档中的手动穿着。前两种直接发送模式会在首次选装和换装时让主模型输出完整 ID 快照。

```html
<!-- outfit:char=["上衣ID","下装ID","鞋ID"] -->
```

局部换衣也记录完整一身，保留未换下的裤子和鞋；搭配使用自身 ID，加上独立补充的单品 ID，不重复列成员。记录仅接受该角色明确分配的候选，存在无效引用的新快照整体忽略。旧版按服装名称记录的标记仍可读取，旧存档的手动穿着及其聊天位置继续兼容；后续有效记录更新当前穿着，重新生成、滑动、编辑和删除楼层时重新解析实际记录。

### 穿搭范围

**专属角色**按穿搭范围和启用的世界书组合保存。选择 **按角色卡** 时，详情为下拉菜单中的目标卡编辑标签，发送时匹配实际游玩的卡。即使两张卡的世界书和人物姓名相同，标签也独立。编辑另一张卡时使用全局启用及目标卡绑定的世界书。需要聊天绑定的世界书时，请在对应聊天里设置。

缺少角色卡或聊天标识的旧标签可手动恢复。切到原来的世界书组合，选择目标范围，在 **信息 → 专属角色** 点击 **恢复旧标签**，再点击 **保存修改**。

只有穿搭范围和世界书组合匹配，且最新一条实际对话提及该角色名时，插件才附上该角色的服装资料。重新生成时跳过待替换的旧回复。资料只用于描写已经在场的人物，提示词要求模型沿用剧情中的出场和换装安排。

保存专属角色会清除该服装的普通 USER／Char 归属。添加多个标签时，标签内的角色都可以穿用。整套搭配需单独设置标签，角色必须符合每件专属单品的归属。清除各组世界书的专属标签后，可重新勾选普通归属。各组角色标签随服装 JSON 备份。

在衣柜侧栏的“穿着”中可切换穿搭范围，手机端入口在分类栏左侧。

| 范围 | USER／Char 选择的隔离方式 |
| --- | --- |
| 全局 | 默认模式，保留已有选择，所有角色卡和聊天共用，首页可设置。 |
| 按角色卡 | 从下拉菜单选择目标角色卡，再在服装详情勾选该角色，或批量应用。首页也可以分配。同一卡的不同单聊沿用该卡选择，群聊发送不使用此范围。 |
| 按聊天 | 每个聊天独立保存；不同角色卡、不同群组下的同名聊天也互不混用。需先打开聊天。 |

打开衣柜时，目标默认跟随当前单聊角色卡。下拉菜单可编辑其他卡的归属，聊天发送始终读取实际聊天的范围。同名角色卡以头像文件名区分，已有归属可继续使用。

服装素材、标签、收藏、最近使用和发送设置仍在当前脚本共用，范围仅隔离 USER／Char 的应用选择。首次使用某张卡或聊天的独立范围时没有应用服装，需自行勾选。勾选归属时使用已保存的服装资料，详情草稿仍可继续编辑。切换服装、切换衣柜或关闭面板时，如有草稿会提示放弃或继续编辑。没有对应角色卡或聊天时，不会回退发送全局选择。范围偏好和各范围选择均保存在脚本变量中。

## 衣柜设置

点击面板右上角齿轮打开设置。各设置页修改后均需点击该页的“保存”。

### 导入／导出数据

设置侧栏的“导入／导出数据”用于迁移五类设置：发送内容、USER 模板、Char 模板、图片模板、描述生成提示词。

- **导出数据**：下载 `衣柜设置.json`，只包含已经保存的上述设置。未保存的表单修改不导出，空衣柜也可导出。
- **导入数据**：选择该文件，全部校验通过后一次替换这五类设置，并立即刷新相应表单。文件错误或保存失败时保留原设置。
- **API 信息始终排除**：不导出连接方式、地址、模型、密钥、温度、Token 参数或其他 API 配置；导入文件夹带的 API 字段也不会写入或覆盖当前连接。
- **服装与原图单独备份**：此文件不含服装、图片、标签或 USER／Char 应用选择；这些数据继续使用衣柜中的“导入服装”和“导出服装”。

文件格式为 `format: "tw-wardrobe-settings"`、`version: 1`，与服装 JSON 分开。导入发送类型时仍检查已应用服装是否具备所需的描述或图片，避免导入后无法发送。

### API 连接

此处的连接用于**生成服装描述、独立 API 选装和测试连接**。正常聊天仍使用 SillyTavern 当前的聊天连接。

| 连接方式 | 配置方式 |
| --- | --- |
| 使用酒馆连接 | 默认选项，沿用酒馆当前连接，无需另外填写接口和密钥。 |
| 自定义（OpenAI 兼容） | 填写服务商提供的接口地址、API Key、模型、温度及最大回复 Token。地址必须使用 HTTP 或 HTTPS。 |

自定义连接可点击“获取模型”再从列表选择，也可手动输入模型名。接口没有返回模型列表时，仍可手动填写模型并测试连接。

“测试连接”使用表单当前值发送一条要求回复 `OK` 的短请求，收到非空文本即视为连接成功；它不验证模型是否支持看图，也不代表配置已保存。测试后点击“保存”，服装描述生成才会使用这份配置。连接测试与描述生成均不携带聊天历史，不写入聊天记录。

API 连接配置（含 API Key）保存在当前酒馆站点的浏览器 `localStorage` 中，按脚本 ID 隔离，不再写入脚本变量，也不会随脚本导出。更新原脚本并启用后，会先保存旧连接到本机，再删除整个旧 `wardrobe_api` 变量；本机已有连接时优先保留本机配置。若迁移失败，API 页会提示错误，旧变量保留以免丢失配置，处理成功前不要分享脚本。

本地存储仍是明文，同一站点的脚本及浏览器开发者工具可以读取，不是加密保险箱。更换浏览器、设备、酒馆站点或脚本 ID，或清除站点数据后，需要重新配置 API。此前已导出或分享的文件不会被自动清理；如果文件含有密钥，应在服务商处撤销并重新生成。

### 发送内容与位置

| 内容类型 | 实际发送内容 | 应用前要求 |
| --- | --- | --- |
| 文字描述 | USER／Char 对应的文字模板 | 每件服装有非空描述 |
| 图片 | 图片提示词＋参考图，默认省略已保存的服装描述 | 每件服装有图片，聊天模型与连接支持图片输入 |
| 文字＋图片 | 角色文字模板＋图片提示词＋参考图 | 每件服装同时有描述和图片，聊天模型与连接支持图片输入 |

图片以真实的 `image_url` 内容块发送，不是把图片地址作为文字发送。“图片”模式仍附带图片模板中的文字，以说明服饰参考范围；自定义图片模板也可以主动引用描述变量。

在「衣柜设置 → 发送内容 → 参考图画质」选择 **压缩参考图**或**原图**，点击「保存」。压缩参考图是默认选项，保持比例，长边最多 **1280 像素**，使用 **JPEG 质量 0.82**，透明区域合成白底。小图在压缩后更小时才使用 JPEG。原图选项保留原始尺寸和格式，请求体积可能更大。此设置适用于直接聊天和独立选装的参考图，随设置备份保存。服装描述识图和服装备份始终使用原图。

| 注入位置 | 行为 |
| --- | --- |
| 系统提示末尾 | 追加到请求开头连续系统消息中的最后一条；没有系统前缀时，在开头新增系统消息。 |
| 上下文末尾 | 在整个请求消息数组最后新增一条系统消息。 |
| 用户消息末尾 | 追加到最后一条用户消息；没有用户消息时，在末尾新增用户消息。 |

上述位置用于直接发送模式。独立选装固定在系统前缀附加当前穿搭，图片另作参考消息。切换发送类型时，脚本会检查当前范围中已应用的服装是否满足新类型要求，缺少描述或图片时会提示保存失败。

### USER、Char 与图片模板

USER 和 Char 分别有“单条模板”和“衣柜模式”模板：该角色分配 **1 条候选**时使用单条模板，分配**多条候选**时使用衣柜模板。两者独立计算；保存的搭配无论包含多少成员，都计一条候选。模板字段仍为 `single` 和 `wardrobe`，旧设置文件可继续导入。

每组发送内容都会先标明 USER／Char 及其当前名称，并说明文字和紧随其后的图片只对应该角色，另一角色只能使用自己清单中列出的服装。这份归属说明在自定义模板下也会保留；同件服装只有明确分配给两边时，才会出现在两份清单中。

图片模板也分为单条与衣柜两种，仅在含图发送方式下附加。默认模板提供可选服装资料，完整当前穿着由插件另行标明；候选不会被当成全部已经穿上的衣服，也不会限制只能选一条。

默认文字及图片模板要求禁止编造服装，并将细节分散融入动作、触感和环境互动，每次只带出一两个细节。固定穿搭规则独立于自定义模板，支持自由搭配、整套选择和合理机会换装，优先于模板中旧的“只选一条”“转场即换装”要求。发送内容附带实际标签，图片模式也会携带；未分组的服装不补造场景标签。

更新脚本时，仍与两代已知原始默认值完全相同的模板会自动使用新版内容；已经编辑过的自定义模板保留。Char 模板使用小写变量 `{{char}}`。

文字或图文模式下，自定义模板如果没有引用 `{{description}}` 或 `{{outfits}}`，插件会在候选清单中补齐描述，确保 AI 仍有完整选装依据；自定义模板原文保持不变。纯图片模式不会自动附加保存的描述，仍可通过图片模板主动引用描述变量。

| 变量 | 含义 |
| --- | --- |
| `{{user}}` | 当前聊天的用户名 |
| `{{char}}` | 当前聊天的角色名 |
| `{{wearer}}` | 这组服装所属的 USER 或 Char 的实际名称 |
| `{{name}}` | 候选服装名称；多条时以顿号连接 |
| `{{description}}` | 候选服装描述；多条时以换行连接 |
| `{{outfits}}` | 带编号、类型、分类和 ID 的候选名称与描述列表 |
| `{{count}}` | 当前角色明确分配的候选记录数；保存的搭配无论包含多少成员都计为 1 |

例如，单条文字模板可以写为：

```text
{{wearer}} 的可选服装「{{name}}」：
{{description}}
选用后请在后续描写中保持服装细节一致。
```

模板只替换表中变量，不执行代码，也不会再次解释服装名称或描述中原有的模板标记。

### 描述生成提示词

“描述生成”页可分别编辑：

- **整套描述**：默认用 `【品类】` 标签把每件服饰及其层叠、连接关系合并进一段描述，整段 400–900 字。使用默认提示词且开启 AI 分类时，即使图中只有一件服饰也归入 `outfits`（套装）。一键识图使用同一提示词。
- **单品描述**：默认只还原画面中最主体的一件服饰。开启 AI 分类时，按主体服饰的结构从除 `outfits`（套装）之外的九个分类中选一个。

整套模式按件分配篇幅，简单件 60–100 字，复杂常规件 120–200 字，特殊剪裁件 200–300 字。单品模式的对应范围为 80–150 字、150–250 字、250–350 字。两种模式都按图块和连接线拆解特殊剪裁件，说明受力锚点、连接路径、颜色与纹样分区及透光层级。

自定义提示词时，可以使用 `{{name}}`（当前已保存的服装名称）与 `{{category}}`（中文分类名称）。保存提示词后，到详情“描述”页选择类型并生成。

如果希望 AI 同时命名服装，可在任一种提示词中要求仅返回 JSON，例如：

```json
{"name":"黑金长外套","description":"黑色长款外套，搭配金色滚边与腰带。","category":"coats","tags":["日常","正式"]}
```

脚本会分别将 `name` 和 `description` 填入名称与描述编辑框，也兼容完整的 JSON 代码块。两个字段必须为非空字符串；JSON 格式或字段错误时会显示提示并保留原内容。点击“保存修改”或勾选穿着归属后，USER／Char 的单条、衣柜模板即可使用更新后的 `{{name}}`、`{{description}}` 和 `{{outfits}}`。

手动在描述框粘贴 JSON 后保存也使用相同字段：`name` 更新名称，`description` 提取为唯一描述正文，`category` 支持内置标识或对应中文分类名，未知分类保留信息页的选择；`tags` 按名称追加标签，同名复用，新标签直接创建，空数组不清空已有标签。手动保存不受“AI 分类／AI 标签”开关影响，也不把未知 `category` 当作旧版标签。格式或存储错误时保留原 JSON 草稿及原存档。保存后的资料供 USER、Char、图片模板取值，`{{user}}`、`{{char}}`、`{{wearer}}`、`{{name}}`、`{{description}}`、`{{outfits}}`、`{{count}}` 均按现有模板规则生效。

“描述”页的 **AI 分类** 和 **AI 标签** 分别选择开启或关闭，默认均开启；切换服装保留当前选择，同时适用于单张和一键识图。关闭的项目不要求 AI 判断，即使模型返回对应字段也不会写入，原分类和手动标签保留，关闭 AI 标签时也不会弹出新标签确认。开启时，生成请求会附带可选分类或衣柜中全部现有标签，要求 AI 根据图片判断 `category`（服装分类）或 `tags`（标签分组）。`category` 使用 `tops` 上装、`bottoms` 下装、`dresses` 连衣裙、`coats` 外套、`underwear` 内衣、`socks` 袜子、`shoes` 鞋子、`accessories` 配饰、`outfits` 套装或 `other` 其他，也兼容对应中文分类名。`tags` 使用标签名称数组，例如 `["居家", "夏季"]`；优先匹配已有标签，只有没有合适标签时才提议新标签。新标签创建前会弹出确认框，列出本张图片建议的新标签；同意后创建并归组，取消则跳过这些新标签，已有标签和其他识图结果仍保留。单张和一键识图都遵守此规则，已有标签直接复用，无需确认。已开启的分类与标签在单张识图后立即保存，名称与描述仍需保存或应用；一键识图会同时保存名称、描述和已开启的字段。识别出的标签追加到原有标签，不覆盖手动标签，`tags: []` 不清空原标签。

请求末尾会附加最新输出格式，自定义提示词仍保留。兼容旧版把 `category` 数组或非内置分类的字符串当作标签的回复，此时保留原服装分类；旧 JSON 只有 `name`、`description` 时保留原分类和标签，纯文本回复仍只更新描述编辑框。

两种默认提示词都以衣物结构为主，略过参考图人物的身材、外貌和姿势。背面与固定结构优先采用直接证据，证据不足时按款式补全。常规款不写裸露或遮挡范围。未编辑过的已知旧默认提示词自动升级，其他已保存提示词按原文加载。模型生成的内容可在编辑框中修改，再保存或应用。

## 数据保存、备份与恢复

| 数据 | 保存范围 |
| --- | --- |
| 服装信息、图片路径、标签 | 当前脚本的变量，在同一脚本可用的聊天间共享 |
| 原图文件 | 酒馆当前用户的数据目录下 `user/images/tavern_wardrobe/` |
| API 配置（含密钥） | 当前酒馆站点的浏览器本地存储，按脚本 ID 隔离，不随脚本导出 |
| 发送设置、角色／图片模板、描述生成提示词 | 当前脚本的变量 |
| 穿搭范围、USER／Char 已应用的服装 ID | 当前脚本的变量，按全局、角色卡或聊天分别读取；首页可设置全局选择 |

### 图片保存与旧数据迁移

导入图片和恢复 JSON 时，通过酒馆原生 `/api/images/upload` 接口将 Base64 解码成 PNG、JPG 或 WebP 文件，保留原图字节，不重新压缩或裁剪。通常位于 `SillyTavern/data/<用户>/user/images/tavern_wardrobe/`；以实际配置的数据目录为准。脚本存档只记录 `user/images/tavern_wardrobe/文件名.png` 这样的相对路径。

新上传的图片以**原图字节的 SHA-256 派生固定 UUID v8 文件名**：取摘要前 128 位并设置版本与变体位。文件名不受服装名、源文件名、备份 ID 或导入次数影响；同样的原图字节与格式得到同一路径，多件服装可以共用。普通导入、JSON 恢复、替换图片和旧内嵌图片迁移均使用此规则。服装记录 ID 仍独立，支持“保留两份”；导入查重仍使用完整 SHA-256。视觉相同但经过重新编码或修改元数据的图片，字节不同，文件名也会不同。已有的随机文件名保持可读，不自动批量改名或清理历史重复文件。

列表和预览直接加载图片路径，由浏览器处理缓存，列表使用懒加载。聊天发图、生成描述或导出备份时，才读取文件并恢复为图片数据地址；聊天额外生成压缩参考图，生成描述与备份继续使用原图。同一图片在脚本本次运行期间共用读取及参考图缓存，删除无引用的图片或卸载时释放。

更新原脚本后，启动会逐张迁移存档中已有的 `data:image`。每张图片上传并成功保存路径后，才替换对应的内嵌数据；失败时保留尚未迁移的原图，下次启动继续，不需要手动重新导入。迁移保留服装信息、标签和 USER／Char 应用状态，也不会重填正在编辑的详情表单。

删除服装或“删除图片”时，先保存存档，再调用 `/api/images/delete` 清理不再被服装引用的文件。保存失败不会删除原图；文件删除失败会记入浏览器控制台，不撤销已保存的删除操作。导入中途失败或存档保存失败时，会尝试清理本批新上传的文件。

### 导出

- 左侧“导出服装”或手机底部“导出”：先打开与导入同样样式的弹窗，选择 SFW、NSFW 或自建衣柜，再选择“全部服装”或“仅有描述的服装”。默认当前衣柜、全部服装，保留原有全量备份方式和空标签；确认前显示符合条件的数量，文件名包含所选衣柜名称。
- “仅有描述的服装”：只导出已保存非空描述的记录，自动跳过未识图、没有描述及仅有空白的服装；手动填写的描述也可导出。单张识图生成的描述需先保存；一键识图的自动保存结果可直接导出。搭配使用成员描述，只有全部成员都有描述且搭配正文非空时才导出，并一并打包成员，保证可重新导入。
- 详情“导出”：先保存当前编辑，再导出这一件服装及其关联标签。
- 多选后的“导出”：导出所选服装及其关联标签。

JSON 文件标记为 `format: "tw-wardrobe"`、`version: 1`，包含 `groups` 和 `items` 数组；分组通过可选的 `filters` 数组保存所属分类或快捷筛选，搭配通过可选的 `componentIds` 保存成员关系。新版可读取旧备份；要完整恢复分组归属及搭配关系，目标脚本也需更新到支持这些字段的版本。导出时会读取原图，以 Base64 数据地址嵌入，备份可跨设备恢复。较大的原图仍会增加备份文件的体积；聊天含图请求使用压缩参考副本，原图不会作为 Base64 反复写入日常存档。图片读取失败时会提示错误，不生成缺失原图的备份。

**服装 JSON 不包含 API 配置、密钥、发送设置、模板、描述生成提示词或角色应用状态。** 发送设置、模板和描述生成提示词可通过“衣柜设置 → 导入／导出数据”单独迁移；API 连接需要在目标酒馆自行配置。

### 恢复与合并

通过“导入服装”选择本插件导出的 JSON，也可以同时选择多份 JSON 或图片。如果备份已经托管，点击 **添加 JSON 链接**，粘贴直接返回备份内容的 HTTP 或 HTTPS 地址，再点击 **导入所选**。跨站下载需要文件来源允许酒馆页面跨域读取（CORS）。浏览器直接下载备份，再逐张保存图片。

GitHub Release 的附件禁止网页跨域读取时，插件会尝试使用酒馆已启用且无需登录的内置 CORS 代理。如果代理不可用，直接在浏览器打开附件链接下载，再用 **添加图片/文件** 选择下载好的 JSON。

同时兼容 [Outfit Manager](https://github.com/wenshui012/Outfit-Manager) 导出的 User、单角色、全部角色和完整备份 JSON，仍使用“导入服装”入口，无需转换文件：

- 保留服装和单品的名称、描述、原图、收藏，纯文字记录也可导入。整套穿搭归入“套装”，单品优先匹配现有分类，其余归入“配饰”。
- 场景 `sceneTag` 转为本衣柜标签；没有场景时，使用原分类和子分类作为标签，同名标签复用。
- 完整备份合并 User、角色及通用衣柜，全部角色备份合并其中所有角色；不额外导入预设中的服装副本。
- 支持内嵌 `imageData` 和通过 `_assets` 打包的服务端原图；备份只有图片路径却缺少原图时，整批导入失败并提示重新导出。
- 对方的套装搭配关系不迁移，关联单品作为独立服装导入；不迁移对方的应用选择、API、模板或其他设置，导入后按本衣柜方式重新选择 USER／Char。

- 导入按**名称（去除首尾空白）＋原图字节的 SHA-256 哈希**识别重复项；图片保存路径或备份中的 ID 不影响识别。同名不同图、同图不同名视为不同服装；纯文字服装按名称与空图片匹配。搭配按名称与成员的名称、原图指纹及顺序匹配，重导入生成的新 ID 不影响查重。
- 发现重复项时可选**跳过／覆盖／保留两份**，所选方式用于本批所有重复项，同一批内部的重复项也会处理。取消或按 Escape 放弃整批导入，不改动原存档。
- 跳过不上传图片。覆盖只更新 JSON 明确提供的字段，保留原 ID、原图、应用关联和较新的最近使用时间。纯图片没有可覆盖的服装资料，选择覆盖时按跳过处理。选择保留两份会生成新 ID。新增服装由用户自行分配给 USER／Char，同名标签继续复用。
- 同一批文件全部读取与校验成功后才保存。每个 JSON 链接最多等待 60 秒，涵盖直连、代理和响应读取。超时后可保留本次勾选重试。
- 兼容旧版内嵌图片的 JSON，恢复时重新上传为图片文件。只有本机图片路径的 JSON 会明确报错；请在原酒馆中重新导出包含原图的备份。
- 删除服装会同时移除无引用的图片，并在同次保存中清理全局、所有角色卡和聊天的应用选择。删除前可先导出。

旧版单标签 `groupId` 读取时自动转为多标签 `groupIds` 数组，保存与导出使用新字段；没有标签字段的服装默认为未分组。缺少图片模板的设置会补入默认值。尚未保存共用选择时，首次读取到当前聊天的旧应用状态会将其迁移到脚本变量；旧版 `wardrobe_active_id` 单套选择兼容为 Char 的选择。此后其他聊天的旧状态不会覆盖共用选择，取消全部应用也不会恢复旧选择。

当前穿着在内存中使用 ID 集合，保存为 `current: { user: string[], char: string[] }`，空数组表示尚未确定。旧的单 ID 或 `null` 会在读取入口自动兼容，之后保存为数组。全局、角色卡和聊天范围继续隔离；取消分配或删除某件衣物只清理受影响的当前记录，不清空其余穿着。

## 当前限制与常见问题

遇到异常时，先在当前页面复现问题，再点击搜索框右侧的 **日志 → 导出全部**，将 `衣柜日志.json` 连同操作步骤提供给维护者。也可以点击“复制全部”；筛选只影响查看，复制与导出始终包含全部保留记录。

日志从脚本启动时开始采集，包含衣柜已捕获异常的原始原因及堆栈、衣柜脚本窗口的控制台输出／未捕获异常／未处理 Promise 拒绝，以及衣柜界面内的资源加载失败。Info 记录启动环境、打开界面、数据保存、取消请求和衣柜内容注入等正常运行步骤，Debug 仅记录显式调试输出；不采集酒馆全局控制台、全局异常或其他脚本的资源加载失败。

API 日志覆盖本插件的连接测试、模型列表、单张／批量识图，以及图片上传、读取、删除，记录请求编号、参数摘要、耗时和原始返回结果。图片接口还会记录 HTTP 状态及失败响应文本；酒馆助手封装的生成与模型接口只能记录其实际返回或抛出的信息，无法获取被宿主隐藏的 HTTP 细节。

界面、复制内容和导出文件统一使用**北京时间（UTC+8）**，导出时间保留 `+08:00` 时区偏移。日志只保留本次运行最近 **1000 条**，单条消息和详情各最多 **12000 字符**，刷新页面或重新启用脚本后重新开始，复现后应先导出。已知 API Key、鉴权字段及图片 Base64 会隐藏；日志仍可能包含服装名称、提示词和模型回复，发送前可先查看内容。日志不会自动上传。

| 情况 | 说明或处理方式 |
| --- | --- |
| 搜索后找不到服装 | 搜索与当前分类、标签共同筛选，支持名称、描述、分类、标签和 ID。清空搜索、切回“全部”和所有标签后再检查。 |
| “收藏”“最近使用”没有内容 | 点击卡片右上角爱心可加入收藏；成功应用到 USER 或 Char 后才会留下最近使用记录，旧数据需重新应用一次。两类列表均遵循当前标签和搜索条件。 |
| 想直接新建纯文字服装 | 当前没有独立的新建纯文字入口。可以导入图片、填写描述后，在“信息”页删除图片，保留文字记录；若正在以含图方式应用，需先取消应用或改为文字方式。 |
| 找不到衣柜入口 | 确认源码完整、脚本已启用，并运行在酒馆助手脚本库中；启动时需要酒馆扩展菜单。失败信息会显示为“衣柜插件启动失败”。 |
| 无法勾选可穿者 | “按角色卡”先选目标角色卡，“按聊天”先打开目标聊天。 |
| 提示需要文字描述／图片 | 补充对应数据，或在“发送内容”中选择符合现有数据的类型并保存。 |
| 模型列表为空 | 检查地址、密钥及列表权限，也可手动输入模型名再测试；空列表本身不能证明密钥无效。 |
| 测试连接成功，但无法看图 | 测试只验证文本响应。请确认用于描述生成或正常聊天的相应模型与连接支持图片输入。 |
| 应用了服装，但聊天界面没有新消息 | 应用只影响后续生成请求，属于正常行为。若模型回复没有体现服装，请检查当前聊天选择、已保存模板及聊天补全发送流程。 |

当前测试使用模拟宿主验证逻辑，不代表所有酒馆版本、浏览器、模型或接口均已完成实际联调。
